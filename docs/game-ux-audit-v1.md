# 玩吧：37 款游戏体验审计与优化建议

审核稿 v1 · 2026-09-08 · 面向 Android 手机

## 结论与审核范围

建议下一轮先处理操作清晰度、暂停与存档一致性、经典规则准确性，再增加长期奖励与新关卡。已有游戏数量足够，当前更值得投入的是让每一局容易理解、操作准确、中断后能可靠继续。

本稿覆盖全部 **37 款游戏：23 款单人游戏、14 款人机挑战**。审计基线为 USER_HOUSE 3.10.0、提交 `a7073be7683fd900c38c4e3d2a17e8d37e8c2a1a`，同时考虑本次 Android 独立化。游戏事实来自规则、实现及既有回归资料；下表的优化项是待审核方案，不代表已开发或已验证的缺陷。

证据边界：这是逐款静态审计与重点回归资料复核，不是 37 款所有难度、所有关卡的完整通关测试。Android 首版实测结果另见 [Android 验证记录](android-validation.md)。旧版 Via 验证不等于新版 APK 验证。

本次 APK 必做的独立启动、离线资源、系统返回、存档与备份、图标适配属于已授权改造。下文新增玩法、资产重制和奖励体系等待本稿审核后安排。

## 优先级与投入口径

| 标记 | 含义 |
| --- | --- |
| P0 | 阻止正常使用或可能损害存档，应在发布前处理；需以复现证据确认 |
| P1 | 高频操作、明显预期偏差、重要可用性问题，建议下一轮先做 |
| P2 | 玩法深度、进阶辅助与长期体验 |
| P3 | 可选模式与长期扩展 |
| S / M / L | 单项预计约 0.5–1 / 2–4 / 5–10+ 人日，含实现与针对性回归；不是工期承诺，不宜直接相加 |

“已确认”指代码或已有记录直接支持；“风险待复现”指存在代码路径但尚未证明用户端后果；“增强建议”不表示现有功能损坏。

## 共性问题与建议

| 编号 | 发现与性质 | 推荐改动 | 优先级 / 投入 | 验收标准 |
| --- | --- | --- | --- | --- |
| C01 | 已确认：37 款入口为长列表；手机上查找和续玩成本随数量增加 | 最近游玩、收藏、搜索；有存档时直接显示“继续”与所属模式 | P1 / M | 输入名称可找到全部游戏；收藏跨重启保留；继续与新开局不会混淆 |
| C02 | 已确认：多处小工具按钮及密集棋盘依赖较小点击区域；实际物理尺寸需设备测量 | 工具栏扩大有效热区；扫雷、五子棋等提供缩放、拖动或放大镜；避免仅放大图标而不扩大热区 | P1 / M | 常用独立按钮目标区域达到约 48 dp；密集棋盘有可用精确落点方案，系统栏不遮挡 |
| C03 | 风险待复现：部分旧游戏的延迟动画回调没有统一暂停/会话校验，例如飞行棋飞跃回调 | 使用统一可暂停计时器和本局标识；退出时注销回调；对动画中切后台做专项回归 | P1 / M | 动画中切后台、退出重开 20 次，无后台落子、旧局修改新局或重复结算；若证实存档损坏则升 P0 |
| C04 | 已确认：各游戏的提示、撤销、道具次数和重开清零规则不同 | 道具显示剩余数量与成本；首次使用解释；有损重开明确提示；统一反馈位置 | P1 / M | 使用前知道消耗什么；失败操作不误扣；撤销范围和是否恢复奖励可解释 |
| C05 | 增强建议：独立 App 的“人机挑战”应明确对手是本地电脑 | 去除角色依赖称谓；展示难度、先手和本局目标；保留离线模式 | P1 / S | 入口、规则、结算均无需要联网匹配或酒馆角色的误导 |
| C06 | 已确认：部分游戏依赖颜色判断；Canvas 游戏不能天然提供完整辅助语义 | 颜色搭配符号/纹理；音效、震动分别开关；关键状态提供可读文本 | P2 / L | 色觉差异模式下仍可区分同色对象；关闭声音仍理解成功、失败与危险 |
| C07 | 增强建议：资源体积与首次解码可进一步优化，部分游戏图标约 2 MB | 无损视觉比对后压缩列表缩略图、按需解码；保留高清原稿 | P2 / M | 列表清晰度不降；首次列表可交互时间、峰值内存和安装体积有前后数据 |
| C08 | 已确认：游戏有各自记录口径，记忆、猜数字等已做专用统计 | 进一步分离模式/难度纪录；解释越小越好指标，提供个人最佳提示 | P2 / M | 不把所有游戏强行统一为分数；不同难度不会产生误导性排名 |

触控尺寸参考 [Android 无障碍建议](https://developer.android.com/guide/topics/ui/accessibility/views/apps-views)。48 dp 是常用控件触控目标建议；不能把 16×16 棋盘每格直接硬塞成 48 dp，应配合缩放与定位方案。

## 三款重点游戏的审核方案

### 三维弹球：清晰度应该覆盖运动中的球台

已完成完整引擎接入；目前高清层重点是静态球台，动态元素仍受原版低分辨率素材约束。仅再放大背景无法消除运动时的清晰度差异。建议分两步：先改善移动端布局、任务信息和触控区；再逐组重绘挡板、球、弹簧等动态素材，检查透视、遮挡及碰撞对齐。可以用 imagegen 重绘缺失/低清素材，但不能只凭观感替换碰撞几何。

另外，当前同页返回可继续完整球局；进程重启/刷新后的便携存档只保留分数、常规球数和军衔，从新球开始。应在退出与恢复界面说明这个差异，避免用户以为球的位置和任务状态也会恢复。

### 空当接龙：优先减少等待与误操作

安全归档、随步归档、双点归档已经存在。双点识别窗口约400毫秒，一些单点动作会等待判定，这是手感优化的重点。建议先测量响应时延，调整事件策略并保留系统可用性，再加拖牌；不能简单删除等待导致双点误搬牌。自动收尾要基于安全性判断，归档与手动移动必须作为同一个撤销单元。牌局编号及同局重玩能让用户反馈具体难局，也方便回归。

### 消消乐：从特效丰富走向目标丰富

已有四连、五连、L/T和特效组合，也有破冰及无限模式。建议下轮做组合教学、颜色收集＋破冰等新混合目标、障碍层次与关卡节奏。当前星币属于本局，结束或重开清零；跨局钱包、成就和每日奖励会改变存档与经济规则，建议明确审核后单独实施。先采用离线可解释奖励，避免为了“奖励多”引入不必要的联网或付费系统。
