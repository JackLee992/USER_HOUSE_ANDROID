# content1 真机性能基线

设备 NTH-AN00，Android 12；GeckoView 155.0.1 debug，设备像素比 3，物理屏幕 1080×2340。采样时显示模式为 60 Hz，支持 120 Hz。没有调整 CPU、系统省电、全局 WebView 或刷新率设置。

`tests/android-compat-performance.mjs` 使用独立 rAF 观察器与 50 ms 定时器记录调度间隔，没有替换游戏 rAF、修改物理步进或注入游戏状态。操作是 WebDriver 真实触控。rAF 频率不等于 GPU 最终呈现帧率；Gecko 不提供 longtask PerformanceObserver，结果为不可用，不能记为零长任务。

| 场景 | 时长 | rAF均值 | 间隔P95 | >50ms间隔 | 画布物理像素 |
|---|---:|---:|---:|---:|---|
| 泡泡：真实瞄准/释放，末段自然结算 | 32.3s | 20.0Hz | 150.7ms | 259 | 1026×1386 |
| 三消：12次提示后的交换 | 30.8s | 49.5Hz | 33.5ms | 40 | DOM棋盘 |
| 弹球：蓄力发射及双指挡板 | 30.1s | 53.1Hz | 33.5ms | 4 | 引擎332×427，展示996×1283 |
| 跳一跳：蓄力释放及自然失败后下一局 | 32.7s | 59.1Hz | 16.8ms | 4 | 520×640 |

泡泡末段结算停止绘制，因此 20 Hz 不能表示全程活跃绘制性能。随后新局无输入对照 30.1 秒为 **12.47 Hz，P95 100.42 ms，374 个间隔全部超过50ms**；50 ms 定时器额外延迟 P95 2 ms、最大7ms。证据在相邻 `performance-paopao-idle/`。这表明即使没有测试触控和 DOM 查询，泡泡仍有明显绘制/刷新瓶颈；不能把问题归因于触控驱动。

优先验证降低画布 DPR、缓存预裁小精灵、静止场景避免重复整幅绘制。必须保留物理更新时间，不能靠全局限 rAF 让游戏速度降低。后续三档应对同场景真实复测；这些短样本不测量耗电量，也不构成所有游戏流畅承诺。
